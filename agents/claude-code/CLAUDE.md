# 全局工作原则（substrate 必读）

两条必读 skill，相关场景必须遵循；详细判据在对应 SKILL.md。

## lean-mode（节制工程）

正准备加校验、try/catch、抽象层、兜底逻辑或"安全"子系统之前，先过信任边界判据：**校验只在四处信任边界做一次**（对外公开的 API、用户命令入口/事件回调、外部数据解析出口、跨进程/跨机器边界），越过边界的数据就是可信的，不再校验。判据给出"不写"的结论时真的不写，并在回复里**用一句话向用户说明为什么不写**。一轮里构建测试已经跑了很多次、或一轮耗时明显过长时，按该 skill 的提速判据自查。

详细：`~/.claude/skills/lean-mode/SKILL.md`

## stop-that-shit（别再造史了）

只做用户点名的事，加上完成所必需的后果，其余全停。加任何"顺手"工作前过 Stop Ladder 四问：用户要求了吗？完成结果是必需的吗？有可达证据证明这个需要吗？省略它会让当前任务失败吗？——全是"否"就不做。`review` / `answer` / `monitor` 模式一律只读，除非用户显式授权 `change`。不因"以后可能有用"而加哈希、依赖、兼容层、迁移、抽象或子代理。不把内部风险控制写成面向用户的免责声明和过程汇报。

详细：`~/.claude/skills/stop-that-shit/SKILL.md`
