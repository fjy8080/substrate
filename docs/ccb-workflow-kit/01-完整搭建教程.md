# 从零搭建 CCB 多 Agent 工作流

本教程面向第一次配置的同事。示例是 Linux、macOS 或 Windows 的 WSL2；原生 Windows 请优先在 Ubuntu WSL2 中操作，避免 tmux、路径和终端兼容性问题。

## 0. 先确认你具备的条件

- 一个正常可用的 Git 项目，且有自己可登录的 Git 账号。
- 本人的 ChatGPT/Codex 账号和 Anthropic/Claude 账号；OpenCode 和 cc-switch 是可选项。
- Node.js 18 或更高版本（建议当前 LTS）、npm、Git、tmux、bash。
- 不要使用别人的 `~/.codex`、`~/.claude`、`~/.config/opencode`、`.ccb` 或 cc-switch 数据库；它们可能含会话与密钥。

Ubuntu/WSL2 的依赖安装：

```bash
sudo apt update
sudo apt install -y git tmux curl ca-certificates
# Node.js 请按 nvm 或 Node.js 官方说明安装；安装后确认：
node --version
npm --version
git --version
tmux -V
```

macOS 可使用 Homebrew 安装 `git tmux node`；Windows 使用 PowerShell 安装 WSL2 后，在 Ubuntu 终端继续本教程。

## 1. 安装四个 CLI（先各自单独运行成功）

### 1.1 Codex CLI（必需）

安装方式和登录入口以 OpenAI 的最新官方文档为准。安装完成后，在普通终端运行：

```bash
codex --version
codex
```

按界面提示用**你自己的** ChatGPT/OpenAI 账号登录。完成一条只读测试后退出。Codex 的用户级配置通常位于 `~/.codex/config.toml`；项目级规则应放项目根目录的 `AGENTS.md`，不要把账号或 Provider URL 写进项目配置。

### 1.2 Claude Code（必需）

按 Anthropic 官方文档安装 Claude Code 后：

```bash
claude --version
claude
```

完成本人账号登录并退出。不要从他人电脑复制 `.claude.json`、`~/.claude/` 或环境变量。

### 1.3 OpenCode（可选，但本模板有独立窗口）

按 OpenCode 官方文档安装并登录：

```bash
opencode --version
opencode
```

如果暂时没有 OpenCode，后续请从 CCB 配置中删掉 `opencode = "opencode:opencode"` 这一行；其余 7 角色照常可用。

### 1.4 cc-switch（可选）

cc-switch 是本机账号/模型切换辅助工具，不是 CCB 的依赖。只有同事确实需要在多个本人账号或服务配置之间切换时才安装。它的本地数据库和日志可能含授权信息：**绝不复制、同步或打包**。先独立打开并按它自己的界面完成本人的登录与配置，再开始 CCB。

## 2. 安装 CCB

CCB 是终端内的可视化协作调度器，负责启动 provider 窗格、隔离会话并投递 agent 间任务。安装：

```bash
npm install -g @seemseam/ccb@latest
ccb version
ccb doctor
```

若 `ccb` 找不到，重新打开终端，或确认 npm 的全局 bin 路径在 `PATH`：

```bash
npm prefix -g
npm bin -g 2>/dev/null || true
command -v ccb
```

不要在正在运行其他 CCB 项目的目录里执行 `ccb kill`、`ccb cleanup` 或 `ccb clear`；这些命令属于目标项目的运行控制。

## 3. 解压本包并运行只读前检

```bash
cd /解压后的/CCB多Agent协作工作流搭建包_2026-08-08
chmod +x scripts/*.sh
./scripts/preflight.sh
```

前检只读取命令版本和当前目录，不写文件、不启动 agent。必需项 `git`、`tmux`、`node/npm`、`ccb`、`codex`、`claude` 都通过后再继续。OpenCode 和 cc-switch 显示“可选未安装”并不阻断。

## 4. 为一个项目安装模板

首先确认目标项目干净且路径正确：

```bash
cd /你的/项目
git status --short
git rev-parse --show-toplevel
```

然后从本包目录运行：

```bash
./scripts/bootstrap-ccb-project.sh /你的/项目
```

脚本只会创建缺失文件；发现已有 `.ccb/ccb.config`、`.ccb/ccb_memory.md`、`AGENTS.md` 或 `.gitignore` 时会停止，不会覆盖。此时请人工比较并合并模板，禁止盲目替换已有项目规则。

脚本创建后，检查这些文件：

```text
项目根目录/
├── .ccb/
│   ├── ccb.config       # CCB 拓扑；本地配置，默认不提交
│   └── ccb_memory.md    # 团队工作约束；可按团队策略提交
├── .codex/config.toml   # 可选的项目级 Codex 安全默认值
├── AGENTS.md            # 项目规则模板，必须改成项目真实规则
└── .gitignore           # 防止 CCB 运行态和凭据入库
```

## 5. 按账号能力调整 CCB 配置

打开 `.ccb/ccb.config`。模板使用当前工作流的七个职责：

| Agent | Provider | 职责 | 写权限 |
| --- | --- | --- | --- |
| `main` | Codex | 调度、授权、最终结论 | 否（除非用户明确授权） |
| `reviewer` | Codex | 每轮全新只读审查 | 否 |
| `developer` | Claude | 唯一代码实现与修复者 | 是，仅其 worktree |
| `knowledge_keeper` | Claude | 开发停止后的文档/记忆 | 是，且不与 developer 并发 |
| `task_scout` | Claude | 只读需求/依赖侦察 | 否 |
| `explorer` | Claude | 只读代码/契约/测试映射 | 否 |
| `utility` | Claude | 只读确定性命令/证据 | 否 |

`model` 和 `startup_args` 必须与同事自己的可用订阅或 API 权限相符。模型不可用时，不要猜名称：先在该 provider 的 CLI 内查看可用模型，再修改该 agent 的配置。没有 Claude 账号时，不能假设 Codex 可以无缝替代 Claude；应先将工作流缩减为 Codex main + Codex reviewer，并明确唯一写者。

## 6. 首次启动与登录确认

在项目根目录执行：

```bash
ccb
```

CCB 首次打开的是 tmux 工作台。若弹出 provider 登录提示，只在对应 pane 内完成本人登录。成功后在 CCB 面板检查所有必需 Agent 均显示可用。

不要一启动就派发真实改动。先按 [03-排障与验收.md](03-排障与验收.md) 做只读冒烟测试。首次验证通过后才可用于正式任务。

## 7. 如何安全关闭、更新与恢复

- 正常停止当前项目：在项目根目录执行 `ccb kill`。
- 升级前先确认无活跃任务；npm 安装版使用 `npm install -g @seemseam/ccb@latest`，再运行 `ccb doctor`。
- 修改配置：先 `ccb reload --dry-run`，确认计划无误后才 `ccb reload`；涉及删角色、换 provider、改 worktree 的拓扑变更，先停掉当前项目并重新启动。
- 只诊断：`ccb doctor`、`ccb ping <agent>`、`ccb pend <agent>`。不要把诊断轮询当作正常工作方式。
