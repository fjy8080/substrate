# LLM 产出验收口径

验收任何带 LLM 输出的功能时遵守；完整的盲评操作规程在 `skills/ai-output-review/`。

- **自动化测试默认不调真实大模型**：用 Mock 适配器 + 依赖注入覆盖；Mock 按「固定场景 + Prompt 版本」组织保证可重复；真实模型验证在专门环境手动做、合入前跑一次 smoke 覆盖易触发形态。
- **自动化只验契约，从不验内容深度**：Schema/错误码/结构由测试保；内容深度靠「绝对要素清单」逐项人工判定（达标线 100%），另设严重事实错误率阈值（如 <1%）。
- **可选嵌套字段校验失败一律 tolerate-drop**（置 None/跳过该段），不得 fail-closed 连坐整个主载荷——真实事故：可选 diagram 字段形状错导致整条响应报错。
- **mock 夹具测不出真模型行为**是反复出现的盲区：mock 返回合法形状 ≠ 真模型会输出该形状；「测试通过」先确认测的字符串真的是你以为的字符串。
- **评测口径必须区分用途**：相对百分比门槛（如 95%，用于 A/B 备选模型对比）与绝对要素清单（用于主模型自身验收）不可混用。
- **证据脱敏**：评审证据只存哈希/计数/阈值，禁存产出原文。
- 「契约里有字段」「测试通过」「功能已实现」均不算达标；前端/客户端实际渲染出来的内容才算交付。
