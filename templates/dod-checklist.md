# DoD（Definition of Done）清单

一个任务/PR 满足以下全部条目才算完成，**缺一不可**。按项目实际裁剪后放入项目文档或 PR 模板。

- [ ] **1. 数据迁移**：如涉及，迁移脚本已在真实数据库引擎上实测通过（expand → deploy → contract 顺序，不用 SQLite 替代生产引擎做验证）
- [ ] **2. 契约**：涉及的 API/数据/文档契约已更新，且实现与唯一权威文档一致（文档先行：先改权威文档，再改代码）
- [ ] **3. 实现**：核心逻辑完成，无 TODO 占位充当实现
- [ ] **4. 前端/交互**：如涉及，界面实际渲染验证过（接口有字段 ≠ 页面可见）
- [ ] **5. 正常路径测试**：主流程用例通过
- [ ] **6. 异常路径测试**：错误输入、失败分支、超时/重试用例通过
- [ ] **7. 权限与并发**：权限隔离与并发场景按适用范围覆盖
- [ ] **8. 日志与合规**：日志不含密钥/个人信息；敏感操作有审计痕迹（按项目要求）
- [ ] **9. 独立 Review**：普通任务 ≥1 名未参与实现者审查；高风险任务（鉴权/合规/迁移/文件安全/AI 真值/恢复）≥2 名
- [ ] **10. 合并**：CI 绿、exact reviewed HEAD 被保护、合并后目标分支验证通过
- [ ] **11. 可演示**：端到端可演示/可验证，不是「单元各自绿但串不起来」

## 禁止绕过门禁清单

以下行为在任何情况下都不允许（它们会让上面的清单失效）：

1. 禁止自审自批（实现者计入审查人数）；
2. 禁止 CI 红灯合并（包括 admin bypass、重跑碰运气）；
3. 禁止先改代码后补契约文档；
4. 禁止在production/生产配置开启 Mock；
5. 禁止用轻量替代品（如 SQLite 替代 MySQL、内存版替代真实中间件）冒充集成测试通过；
6. 禁止把「测试被跳过」当「测试通过」呈报——跳过项必须独立列报。

## AI 产出附加项（如任务含 LLM 输出）

- [ ] Mock 测试通过（默认不调真实模型）
- [ ] 真实模型 smoke 覆盖易触发形态
- [ ] 内容质量验收按 `ai-output-review` skill 完成（绝对要素清单 + 盲评）
