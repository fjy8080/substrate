# Pull Request

## 关联 Issue

> 实现 PR 必须使用可检索的关联语句。只有在合入本 PR 后应关闭 Issue 时使用
> `Fixes #N`/`Closes #N`；仅引用背景或跟踪任务时使用 `Refs #N`。
> 发布、版本、纯文档或流程维护 PR 可以没有 Issue，但必须填写对应任务编号与理由。
> 注意：`Fixes` 只在合入**默认分支**时自动关票；base 为其他分支时合并后必须手动关闭并填关闭记录。

- **关闭型关联：** `Fixes #<number>` / `Closes #<number>`
- **引用型关联：** `Refs #<number>`
- **无 Issue 例外及依据：**（仅发布/版本/纯文档/流程维护允许）

## PR 基线元数据

> 由提交者在发起/更新 PR 时根据 Git 实际值填写（隐藏 HTML 注释供 CI 逐项核对，
> 每行一个注释；明文行供人阅读）。**追加提交后必须同步更新，否则 CI 红灯。**

- Base: `develop <!-- base:develop -->`
- Commits: `N <!-- commits:1 -->`
- Files changed: `N <!-- files:1 -->`

## Gate 与独立审查

- [ ] 本 PR 至少由一名未参与实现的人审查
- [ ] 高风险变更（鉴权/合规/迁移/文件安全/AI 真值/恢复）由两名未参与实现的人审查
- [ ] 所需外部证据未被 Mock 或口头结论替代
- [ ] Gate 未满足时保持 No-Go，未请求绕过 CI 或降低安全门槛

## 合并前人工核验（由合并负责人填写）

> 无分支保护时此清单替代平台自动阻断，但不降低 CI、Review 或 DoD 标准；
> **有新提交后全部核验作废，必须重新执行。**

- [ ] 当前 PR 的所有 CI 检查均为绿色，或不适用项有书面说明
- [ ] 核验的是当前最新提交（HEAD SHA）：`待填写`
- [ ] 普通 PR 已有 1 名未参与实现者 Approve；高风险 PR 已有 2 名
- [ ] 所有 Review 意见和会话已解决
- [ ] PR 模板、DoD、契约文档和所需外部证据均已完成
- [ ] PR 无冲突，基线仍为预期分支，未直接 Push 主干
- [ ] 合并负责人已留言：`GO / HEAD=<SHA> / CI=GREEN / REVIEW=<人数> / DOD=PASS`

### Issue 关闭语义核对

- [ ] 关闭型关联与本 PR 的实际交付范围一致；不应关闭的 Issue 使用 `Refs` 而非 `Fixes`
- [ ] Issue 已有 exact HEAD、CI、Review、验证结果记录，或合并后由验收人补齐
- [ ] 验证失败、CI 未完成或 Review 未完成时不关闭 Issue
